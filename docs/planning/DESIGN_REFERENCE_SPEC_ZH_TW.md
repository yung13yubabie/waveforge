# WaveForge 歌曲編輯工作台設計與參考核對

核對日期：2026 年 10 月 5 日。用途：供 WaveForge 介面、互動與分階段實作整合。這份文件提出設計與驗收條件；未聲稱以下新增功能已實作。

## 結論

WaveForge 應以「選一句、看懂差異、試改、同音量比較、隨時退回」為主要工作流。Best Designs on X 提供作品層次的參考；新增 13 個站點提供元件、動態與版面素材，但不需要逐一安裝。最值得採用的是有來源感的面板展開、持續存在的播放控制、清楚的切換狀態，以及可收合但不丟失上下文的工作區。

目前已知程式底子是單曲母帶處理與四個分離音軌的混音；尚缺真正多片段時間軸和專案持久化。先補這些基礎，才能可靠支援替換錄音、AI 音色、改詞重唱，以及逐音／逐字的音高和節奏編輯。視覺稿必須標出「可用、需設定、開發中」，不可讓未接引擎的控制項看起來已能處理聲音。

## 精選 4 組值得採用的互動

### 1 從選中的句子展開對應工具

參考 [Blendy](https://blendy.tahazsh.com/) 與 [60fps Circle Menu Dropdown Morph](https://60fps.design/shots/circle-menu-dropdown-morph-interaction)。Blendy 範例已實際點開；Circle 頁面描述按鈕展開、選單顯示、收回原位置，影片播放器亦可用，但本輪未量測動畫曲線。

WaveForge：點「副歌第 2 句」的工具入口後，右側顯示該句的音準／節奏／人聲工具。選中邊框與面板標題先立即更新，再做短距離淡入或擴展；關閉回到原句且保留播放時間、捲動與選取。不把整個工作台模糊到無法讀取。

驗收：動畫中連點、切換另一句或按 Esc，都只剩一個正確面板；沒有殘留遮罩；鍵盤焦點回到來源按鈕。減少動態模式直接換狀態，保留相同功能。優先用既有元件／CSS；Blendy 只有在來源關係確實改善理解時才評估加入。

### 2 小型操作面板擴展成完整編輯器

參考 [SSGOI YouTube Music Home → Now Playing](https://ssgoi.dev/showcase/youtube-music-web) 與 [60fps Recollect Sheet to Page](https://60fps.design/shots/recollect-pro-bottom-sheet-to-page-interaction)。SSGOI 展示已在瀏覽器打開，明確呈現背景保留的 sheet；Recollect 的細節來自該 shot 公開文字描述，不聲稱親測原 app。

WaveForge：桌面下方編輯器可展開；小螢幕從逐句列表打開完整音高／歌詞編輯器。外層專案、時間位置與循環仍保留。關閉後回到原來一句；播放控制在空間上穩定，不跟著卡片飛走。

驗收：展開不重建音訊引擎、不重新開始播放、不取消錄音或背景處理；瀏覽器返回與可見返回鍵行為一致；不得用滑動手勢作唯一返回方法。SSGOI 程式為 MIT，但 demo 品牌與封面不移植。已有適合的面板架構時，不另裝路由轉場框架。

### 3 離散開關立即顯示真實終態

參考 [Toggles Simple](https://toggles.dev/toggles/simple)。已確認主題切換效果與元件頁。

WaveForge：主題設定可借其克制的圖示切換。音訊功能則使用自己語意正確的「效果已開／暫時旁路」「循環已開」按鈕，文字、圖示、按下狀態同步。A/B 用清楚的「原版 A」「修改版 B」分段控制，不用太陽／月亮等無關圖示。

驗收：應用狀態立即改變，視覺動畫不延後 DSP 操作；可讀名稱與 pressed／checked 語意正確；切換後焦點不掉；停止動畫仍可辨識狀態。不得從 Toggle 範例推定它已具有音訊旁路、音量匹配或所有無障礙能力。

### 4 穩定導覽與漸進展開

參考 [Navbar Gallery](https://www.navbar.gallery/) 的 Static／Sticky、Side Bar、Search Bar、Breadcrumbs 分類，結合前述 Adi 播放控制。

WaveForge：頂部保持專案、復原與匯出；固定播放列始終可用；左側素材／音軌可收合；右側只顯示選中項目。麵包屑用於「專案 › 主唱 › 副歌第 2 句」，讓使用者知道修改範圍。進階參數收在「細調」，初始只露最常用操作。

驗收：切換工具不改變播放鍵位置；200% 文字縮放仍能到達主要操作；收合不抹掉狀態；鍵盤可跳到素材、時間軸、編輯器、參數與匯出。只借架構，自行實作，不從目錄複製商業網站導覽資產。

### 暫緩的兩種裝飾

**Cuelume 提示音。** [官方 README 的 Sound settings](https://github.com/danielwh2/cuelume) 明寫預設啟用、全音量、不記憶偏好；setEnabled(false) 不停止已播放聲音，且不跟隨 prefers-reduced-motion。這對 DAW 有直接風險。第一版不加入；若日後加入，限使用者主動開啟的匯出完成／失敗提示，且僅在音訊工作完全閒置時播放。播放、錄音、節拍器練習、音高導音和 A/B 期間都不能出現 UI 音。開始錄音前必須確定提示音及殘響已停止，不能只呼叫 setEnabled(false)。UI 聲道永遠不得送入工程的錄音或匯出路由；主喇叭外放仍可能被麥克風收進去，亦要納入測試。

**Monoco 平滑圓角。** 可用於少量大面板，但原生 border-radius 已足夠時不增加依賴。音軌片段、密集標記與選取 handles 不因裝飾改變點擊區域；使用 clip-path 時逐項檢查焦點環、浮動說明與陰影是否裁切。不可讓大量波形元素各自觸發尺寸觀察／SVG 重畫。

## 主工作台與三種人聲模式

### 固定布局

1. 頂部顯示專案、真實儲存狀態、復原／重做、匯出。
2. 播放列提供前一句、播放／暫停、後一句、循環所選、時間和比較。
3. 左側是素材、版本及音軌名稱；中央是多軌時間軸與段落；下方是逐句／逐音編輯；右側是選中內容的參數。
4. 選取範圍始終明示，例如「正在修改：主唱／副歌第 2 句／00:42–00:47」。
5. 背景生成與輸出任務收在任務欄，不把整個專案鎖住。右側控制只能顯示實際引擎支援的能力。

### 替換錄音

白話：「用另一段真實錄音換掉這一句」。選句後可匯入／錄製新版本，設定錄前倒數、起點、提前／延後及接縫。原音保持淡色輪廓，新錄音顯示於版本列，顯示長度差與可能空白。整段平移與拉長／縮短必須分開。試聽後按「使用這個版本」，只換所選範圍，保留原版可撤回。A/B 共用時間與循環，可配伴奏或獨聽。若使用麥克風錄音，裝置與權限必須符合實際平台能力；不可只畫錄音鍵。

驗收：範圍外音訊不變；錄音延遲可校準或手動對齊；接縫沒有明顯爆音；存檔重開後位置、素材和版本仍在。

### AI 音色

白話：「保留這段演唱，嘗試不同的聲音質感」。選擇實際可用且有使用權的模型，先做短句，再選候選版本。保留音高、節奏、咬字等控制只在引擎確實支援時出現。顯示來源、模型、時間、範圍與任務狀態；修改設定後舊預覽標成「尚未更新」。

驗收：播放的是相應生成檔；失敗不顯示成功；候選加入版本列，不覆蓋原音。比較時聽咬字、氣音、尾音、接縫，且做同音量 A/B。模型身份、可用用途與聲音素材授權不可省略。

### 改詞重唱

白話：「改這一句的字，重新產生演唱」。原詞／新詞並列，逐字或音節對時間及音符。可沿用確認過的旋律或調整音符，先試唱一句。新增字數太多時指出時間限制，讓使用者改短、延長該句或重分配音符；不能假設一字固定一音。

驗收：新詞真的被唱出，範圍與旋律符合設定，前後接縫可試聽；原詞、原唱、候選全部可回復。音色轉換不能冒充改詞重唱能力。

## 音感與節奏的細分控制

這些是能力規格；在對應分析／處理引擎可用前，不提供誤導性的可操作滑桿。

| 項目 | 白話 | 控制與視覺證據 | 邊界 |
| --- | --- | --- | --- |
| 音準中心 | 這個音靠不靠近想唱的高度 | 選音符、目標音、上／下微調；原曲線、修改曲線、目標線並列 | 目標來自已確認旋律／音階／參考，不把辨識結果當標準答案 |
| 長音漂移 | 長音是否慢慢往上或往下跑 | 單獨修正緩慢偏移，保留細微起伏 | 不把所有起伏壓成直線 |
| 顫音 | 長音中的規律上下擺動 | 引擎支援時分幅度、速度、開始位置 | 顫音不是唱錯；預設保留自然表情 |
| 轉音與滑音 | 兩個音如何接過去 | 選交界、調過渡長度／形狀，凸顯受影響範圍 | 不因調一個交界改整句 |
| 表情與字句 | 哪個字重、尾音多久 | 逐字音量、漸強弱、尾音，歌詞與包絡線對照 | 氣音／齒音分開；不用主觀感情分數代替操作 |
| 整句升降 | 把整段唱高或唱低 | 半音步進、試聽、保持音色選項 | 改音高與改音色是不同操作 |
| 拍速 | 整首歌走多快 | 每分鐘幾拍、跟拍點按、人工確認 | 自動辨識可錯，不自動重拉整曲 |
| 拍點與第一拍 | 格線從哪裡開始 | 把這裡設為第一拍，原格線與修正格線對照 | 格線錯不能歸咎演唱錯 |
| 進入時間 | 某個字早了或晚了 | 起音點、提前／延後、毫秒或拍數偏移 | 沒可信參考時說相對偏移，不說絕對錯誤 |
| 字音長度 | 一個字拖多久 | 尾端／音節邊界與數值調整 | 與起點平移分開 |
| 對齊拍點 | 靠近指定拍格 | 選格線密度、靠近程度、先預覽 | 不預設全量硬吸附 |
| 律動 | 刻意的早晚與長短交替 | 對指定位置設定或套確認過的節奏參考 | 不用隨機抖動假裝自然 |
| 漸快與漸慢 | 不同段落速度變化 | 進階速度變化軌 | 不強制全曲單一拍速 |

沒有絕對音感的人可按「播放目標音」，用鋼琴導音再聽人聲。原位置用虛線、改後用實線，偏差用箭頭和文字；辨識不確定處標記「請確認」，不生成虛假客觀評分。

音高是唱得高低；音色是同一個音由不同人唱時的質感；共振峰是影響母音／嗓音感覺的聲音特徵，改它不等於換掉完整聲音身份；時間／節奏是何時開始、唱多久、如何對拍。[Celemony 音符編輯說明](https://www.celemony.com/en/melodyne/what-is-melodyne) 及 [共振峰工具](https://helpcenter.celemony.com/M5/doc/melodyneAssistant5/en/M5tour_ToolFormants?env=sonar) 可作術語參考，非界面複製目標。

## A B 比較與資料安全

- 原音永久保留；剪輯、音高、時間與生成結果均以非破壞操作或新版本儲存。
- 復原顯示動作名，例如「副歌第 2 句提前 40 ms」；一次完整拖曳算一步。可只重設音準或節奏。
- A/B 比較同一位置、同一範圍，切換不重頭播放、不遺失循環。旁路只暫時聽原效果，不刪參數。
- 比較時的音量匹配與輸出母帶目標分開；不能以相同峰值冒充聽感音量匹配。估算或不可用時明說；參考 [Noir Labs 原廠說明](https://noirlabs.co/products/volume-buddy)。
- 不將 UI 動畫時間當音訊切換時間；真正的音訊切換、必要平滑過渡與延遲補償由音訊層控制。
- 儲存狀態至少區分「有未儲存修改、儲存中、已儲存、儲存失敗」；沒有持久化就不能顯示已存。
- 匯出明示範圍、主輸出／分軌、格式、取樣率／位元深度與過載檢查。等待、分析、處理、合成、完成、失敗、取消各自呈現。
- 沒有實際進度就只顯示目前階段；不捏造百分比或剩餘時間。輸出綁定專案版本，生成中再編輯時指出完成檔不含後續修改。
- 缺素材時顯示檔名、受影響片段、重新連結與保留工程；失敗保留選取、文字、參數，不把使用者踢回首頁。

## 動態與效能驗收

以下數值是專案建議預算，不是上述站點、Awwwards、Webby 或 FWA 的官方合格線。先記錄測試裝置、瀏覽器、音軌數、素材長度與採樣率，再根據實測調整。

### 動態規則

- 常用按鍵回饋立即可見，裝飾性過渡約 80–140 ms；面板展開約 160–220 ms，最多約 240 ms。操作不可等動畫結束才能生效。
- 波形、音符、時間刻度與拖曳控制使用直接映射，無彈簧超調。游標不因裝飾 easing 跑在聲音前後。
- 動態只表達來源、去向、選取或狀態變化；不用背景粒子、呼吸光暈、連續漸層、滑鼠尾跡、強制滾動或大段 stagger。
- 開啟 prefers-reduced-motion 或應用程式「減少動態」後，取消形變、縮放、位移、彈簧和裝飾序列；使用直接更新或極短淡入。播放游標與必要的聲音資料回饋仍可保留，但提供關閉自動跟隨捲動。
- 同時只做必要區域的過渡。動畫中取消、快速重開、變更選取、視窗縮放都必須到達正確終態。

### 效能規則

- 優先使用 transform／opacity；避免大量 layout、濾鏡模糊、陰影與逐幀 React 全樹更新。
- 波形與頻繁更新資料按可視範圍繪製、快取與分塊；不在每個音符和像素上掛昂貴動畫。預先分析避免阻塞互動；具體 Worker／AudioWorklet 策略由工程依現有架構決定。
- 音訊時鐘是播放位置真實來源；requestAnimationFrame 只呈現位置，不負責精確音訊排程。
- 以 60 Hz 顯示器的約 16.7 ms 畫面預算為設計目標；用性能 trace 和實機長片段測試，不因 CSS 宣稱 60fps 就算合格。
- 在相同基準專案下比較加動態前後的輸入延遲、長任務、記憶體、音訊爆音／掉音。建議 UI 互動回饋 p95 低於 100 ms；若做不到先去掉裝飾，不掩蓋延遲。
- 第一輪至少用現有四分軌長素材連續播放、拖選、縮放、開關面板與 A/B；多軌完成後再加約 16 軌壓力情境。記錄真實結果，不提前宣稱通過。
- 隱藏頁面或收合面板停掉非必要動畫；恢復時依音訊真實位置更新。測試音訊持續播放與瀏覽器省電／背景限制，不做無法保證的承諾。
- 每增加一個依賴都記录增量大小、是否重複現有能力、主執行緒成本、卸載／清理、授權與移除方案。這次參考研究本身不構成安裝全部套件的理由。

## 無障礙與繁中說明驗收

以 [WCAG 2.2](https://www.w3.org/TR/wcag/) 為基礎：一般文字對比至少 4.5:1，關鍵 UI 邊界／狀態與焦點依適用規範檢查；一般目標至少符合 24 CSS px 或規範允許的間距等條件，主要播放與觸控操作以 44 px 設計。

- 主要流程全鍵盤可完成：匯入、選句、播放、變更數值、A/B、復原、保存與匯出。選取／移動／縮放都有非拖曳替代方法。
- 分割面板可用鍵盤調整；開啟對話框或抽屜正確處理焦點，Esc 可退出且焦點返回入口。不能讓焦點落到動畫中的隱藏克隆元素。
- 全域快捷鍵在歌詞、數字或文字輸入中暫停；中文輸入法組字時不攔截 Enter／空白鍵作播放命令。列出快捷鍵，可關閉或重新配置單鍵命令。
- 音軌靜音／獨聽／錄音待命、效果旁路均有文字名稱與狀態語意；資訊不只靠顏色。螢幕閱讀器只播報必要完成／錯誤，不逐幀朗讀游標與音量表。
- 200% 文字縮放、窄螢幕、觸控與高對比模式可到達主要操作。時間軸可以有自身橫向捲動，主要操作不能被永久擠出畫面。
- 說明先用「只調整選中的 3 個音」「把這個字提前一點」「先聽這一句，不會改到其他段落」。進一步展開才顯示音分、Hz、LUFS 等數值。
- 音高／節奏辨識不確定度必須可見；對有意表情不下「唱錯」結論。所有聲音提示都有文字替代，聲音與動態偏好分開設定。

## 分階段交付與自我檢查

### 第一階段 現有核心可靠且好用

清楚呈現單曲波形與四軌混音、處理前後比較、真實處理／匯出狀態、繁中幫助。建立統一字級、空間、按鍵、焦點、面板與狀態規則。不上假多軌、假音準或假 AI 控制。

### 第二階段 建立編輯與保存基礎

專案持久化、素材引用、片段時間位置、真正多軌播放／合成、選取／循環、歷史和非破壞版本。驗收存檔重開與匯出一致性，才展開人聲能力。

### 第三階段 音高節奏與替換錄音

由實際引擎支持的操作逐項開放。每個控制都有聲音變化、可視證據、範圍、復原與比較；對不支援的多聲部素材、噪音或分離瑕疵明說限制。

### 第四階段 AI 音色與改詞重唱

分開驗證兩種能力，使用同一套候選版本與任務狀態。引擎未設好時指出缺項；不以通用旋鈕、卡片動畫或進度條代替聲音結果。

### 每一輪的必做檢查

1. 用一首有主歌、副歌、長音、氣音與明顯拍點的可用測試素材跑完整流程。
2. 完成「選副歌一句 → 找到音高或時間差 → 試改 → 同音量 A/B → 復原一項 → 替換／生成候選 → 保存重開 → 匯出核聽」。尚未實作的階段明確不計通過。
3. 錄下原版與修改版的相同操作過程，逐項檢查來源、選取、焦點、錯誤恢復、文字、聲音、輸出；修改後重跑，而不是只看一張漂亮截圖。
4. 分別檢查滑鼠、純鍵盤、中文輸入法、觸控、減少動態、高對比、200% 文字、失敗／取消和長素材情境。
5. 保存待修問題清單與證據；阻斷工作、錯改範圍、遺失資料、聲音不同步、不可撤回為阻擋交付問題。細節美化不能抵銷這些缺陷。
6. 邀請不依賴絕對音感的使用者完成指定任務，觀察能否自行理解「改哪裡、改了什麼、怎麼回去」；沒有實際測試就不宣稱易用性已驗證。

## 對獎項級品質的可驗證承諾

Awwwards、Webby、FWA 可作企圖心與精緻程度的參照，但「獲獎級」不是可以靠模板數量、動畫數量或自評分數保證的結果。本案可承諾的是完整任務、清楚的原創視覺系統、可存可退回、聲音與畫面一致，以及反覆實測。

[Webby 官方評審標準](https://www.webbyawards.com/judging-criteria/) 將內容、結構／導覽、視覺、功能、互動、創新與整體體驗一起考量；不是只看首頁。可把上述工作流與驗收對應到這些面向。[Awwwards 的 Mobile Excellence 公開文件](https://www.awwwards.com/mobile-excellence-guidelines.pdf) 也涵蓋可用性、效能與易讀性，但它是特定獎項文件，不能當成本案所有獎項的現行統一評分公式。本輪未核實 FWA 的最新完整評分細則，因此不引用未查證權重或保證門檻。

WaveForge 的辨識度應來自：歌曲時間與歌詞始終對得上；看不懂專業術語的人也能修一句；每次嘗試都能聽懂、比較、保存與撤回。當這些做到，再用少量精準動態增進理解。
