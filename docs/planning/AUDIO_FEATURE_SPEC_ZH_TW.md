# WaveForge 音訊編輯與歌聲製作功能規格

研究日期：2026 年 10 月 5 日

## 產品方向

WaveForge 可以從母帶處理與四軌混音，擴充成以人聲編輯為核心的 DAW。DAW 就是把錄音、剪接、旋律、節奏與混音放在同一條時間軸上處理的工作環境。

最重要的體驗是：選一小段聲音，知道正在改什麼，能比較前後差異，再決定要不要保留。使用者不必聽出「這是 C 還是 D」，也不必先學會讀譜。

全部需求都納入產品範圍，但必須拆成不同功能：

1. **修音**：讓已經唱出的音更接近選定旋律
2. **換錄音**：用另一段真人錄音取代原本的人聲
3. **換音色**：盡量保留原本唱的內容、旋律與節奏，換成另一種已授權聲音
4. **改詞重唱**：修改歌詞，根據旋律與字的時長產生新的演唱
5. **看懂與調整音樂**：把旋律高低、節拍、音量與音色變化顯示出來，也能逐項試聽

這五項需要的資料與引擎不同。介面不能只放一個「AI 換聲」按鈕，讓使用者自行猜測會改掉什麼。

本文的功能、介面與數字驗收門檻是**建議規格**，不是既有功能、實測成績或交付日期。既有程式碼實際支援範圍，應由程式碼與音訊測試另行核實。

## 先認識介面上的幾種東西

### 旋律與和聲

- **音高 Pitch**：聲音有多高或多低。像同一個人把「啊」從低處唱到高處
- **音符 Note**：把某一段聲音整理成「從何時開始、唱多高、唱多久」的可編輯方塊。音符是編輯用的整理結果，真實演唱的音高會連續變動
- **半音與音分**：半音是相鄰琴鍵的距離；100 音分等於 1 半音。初學介面可顯示「稍微升高」，進階介面才展開數值
- **旋律曲線 Contour**：這一句整體是在上升、下降，還是在一個音附近起伏。即使不知道音名，也能看懂這條線
- **音階 Scale**：一組可作為參考的音，像一盒彩色筆裡有哪些顏色
- **調性 Key**：一段音樂主要圍繞哪個中心，以及大調、小調等組織方式。歌曲可能換調，也可能沒有明確的單一調性
- **和弦 Chord**：同一時刻一起響的多個音。和弦會隨時間改變，並不等於整首歌的調性

「不在音階裡」不能直接標成唱錯。經過音、藍調音、滑音與刻意的不協和，都可能是作品的一部分。

### 節奏與時間

- **BPM**：每分鐘有多少拍，描述速度，不描述每個音落在哪裡
- **拍點 Beat**：可以跟著點頭或拍手的位置
- **小節第一拍 Downbeat**：例如數「一、二、三、四」時的「一」。找到拍點，不代表已經知道哪一拍是「一」
- **拍號 Meter**：例如每小節四拍、每拍以四分音符計的 4/4 拍。不能只靠 BPM 推出
- **節拍格 Grid**：時間軸上的參考線，可以是一拍、半拍、四分之一拍或三連音
- **起音點／瞬態 Onset／Transient**：一個字、一個鼓點或一個彈奏動作開始的地方。不是所有聲音都有很尖銳的瞬態
- **量化 Quantize**：把選定起音往指定格線靠近，可以只靠近一部分
- **搖擺 Swing**：讓一組細分拍的前後間隔不一樣，形成長短交替的感覺
- **律動 Groove**：一組時間位置、輕重與長短的規律。Swing 是其中一種，隨機移動並不自動等於好律動

### 聲音質地與演唱

- **音色 Timbre**：同樣旋律、同樣音量，聲音仍然讓人覺得明亮、沙啞、厚實或柔和的特徵
- **共振峰 Formant**：與母音及聲腔共鳴有關的頻率形狀。調整它能改變聲音質地；不等於真正換成某位歌手，也不等於音高
- **動態 Dynamics**：一個字、一句話或一段音樂的輕重起伏。壓縮器是在管理這種起伏
- **咬字 Articulation**：子音與母音如何開始、銜接、結束，以及清晰或鬆弛的程度
- **氣息 Breath**：呼吸聲與歌聲中的氣聲。它可能是表情的一部分，不一定需要去除
- **顫音 Vibrato**：持續音附近有規律的音高起伏；不能全部當成走音抹平

波形長得比較高，通常代表振幅較大，不能拿來判斷音比較高。音高需要另一條曲線；頻譜則是不同頻率能量的分布，也不是直接等於樂譜。

## 操作介面的共同規則

- 主畫面保留多軌時間軸，選中片段後，下方切換「聽差別」「旋律」「節奏」「歌詞」「音色」
- 每個工具先用一句白話說明，例如「只把這個字稍微唱高一點」；音名、音分、演算法放在可展開的進階區
- 所有修改先作用於選取範圍；清楚顯示將影響一個字、一句、一軌或整首歌
- 所有建議都可略過。分析不能自行改音訊，也不能把模型猜測寫成確定答案
- 保留原始錄音。修改、生成、換錄音都成為可切換的版本，提供復原與重做
- 基本操作必須能以鍵盤完成；顏色同時配合文字或圖形，不用紅綠色單獨判定對錯
- 切換前後版本時，保持相同播放位置並做短交叉淡化，避免爆音與重新播放造成記憶誤差
- 每次操作後顯示可核對的摘要，例如「這個字提早了 32 毫秒」「這句升高 1 個半音」「只有 14.2–16.8 秒重新產生」

## 第一層 先讓編輯可靠而且聽得懂

### F01 多軌時間軸與非破壞剪接

**白話目的**：把歌曲當成可以移動、裁短、拼接的聲音片段，而不是每次都重新處理整首歌。

**UI 動作**：匯入 → 建立音軌 → 拖曳位置 → 分割／裁短／複製 → 調整淡入淡出。每軌都有獨聽、靜音、音量與左右位置。標籤使用「切成兩段」「只聽這軌」「接縫柔和一點」。

**初學者如何判斷**：先只聽剪接前後各一秒，確認沒有突然中斷、重複字或喀一聲，再放回伴奏中聽。

**接受標準**：未做處理的片段播放與匯出位置一致；在固定取樣率的測試工程中，片段起點誤差不超過 1 個 sample；復原後恢復原片段位置、內容與淡化；關閉重開專案後引用的檔案與設定仍正確。

**限制與依賴**：需先建立音軌、片段、媒體資產及專案儲存模型。僅能拉音量的四個 stem 面板還不構成這種時間軸編輯能力。瀏覽器本機儲存需有容量不足及檔案失聯處理。

**技術來源**：播放與離線渲染可建立於 [W3C Web Audio API](https://www.w3.org/TR/webaudio-1.0/)；專案資料結構及上述驗收是產品設計要求。

### F02 短段循環與前後對照

**白話目的**：即使剛開始覺得「都差不多」，也能把注意力放到一個具體變化，不必憑記憶比較整首歌。

**UI 動作**：框選 3–8 秒 → 開啟循環 → 按「原來／修改後」；可選「只聽人聲」「放回整首聽」「音量拉到接近再比較」。附示範模式：「先把差異放大，再回到自然程度」。

**初學者如何判斷**：每次只問一件事，例如「這個字有比較早進來嗎」「尾音還像自然演唱嗎」。可選「目前聽不出差異」，不給耳力分數，不推斷聽力狀況。

**接受標準**：兩個版本從同一個時間位置播放；對照音量補償不寫入正式混音；旁路時確實回到原訊號；100% 處理與 0% 處理有可驗證的音訊差異；控制項無作用時必須提示原因。

**限制與依賴**：音量匹配只排除「比較大聲所以好像比較好」的一部分影響，不保證任意兩種聲音主觀同樣響。差分監聽只能作輔助，不能把差分越大當作品質越好。

**技術來源**：切換與同步依據 [Web Audio 時間排程及音訊圖](https://www.w3.org/TR/webaudio-1.0/)；對照流程及教學文案為建議設計。

### F03 音軌分離與素材品質提示

**白話目的**：先把想改的人聲從歌曲中取出，減少修人聲時連鼓和鋼琴一起改動。

**UI 動作**：優先「匯入原始人聲／伴奏」；只有整首混音時才選「拆出人聲」。顯示人聲、鼓、貝斯、其他伴奏四軌，提供「只聽殘留聲」與原曲對照。

**初學者如何判斷**：在人聲停下來的地方聽是否仍有鼓、鋼琴；在伴奏軌聽是否還聽得到原歌詞；在人聲尾音聽是否有水聲或破碎感。

**接受標準**：分離結果保留共同起點與正確總長；四軌匯入後不因不同裁切而錯位；來源、模型、版本、取樣率與分離日期可追溯；低品質結果不自動標成「純淨人聲」。

**限制與依賴**：分離不是把原錄音完整拿回來。「人聲 stem」可能仍有和聲、合唱、殘響及樂器。**單旋律**是同一時間只有一條主要旋律，與音檔是 mono 或 stereo 的**單／雙聲道**不同。立體聲主唱可以是單旋律，單聲道合唱仍可能是多旋律。

**技術來源**：[Demucs 官方專案](https://github.com/facebookresearch/demucs)支援常見四類來源；不把四分軌能力推廣為任意樂器的精確獨立控制。

### F04 音高曲線與可讀的音符

**白話目的**：看出一句歌往上、往下、哪裡晃動，以及每個字大約唱多久。

**UI 動作**：選單旋律人聲 →「看旋律」→ 顯示原始音高曲線與整理後音符；可以手動合併或切開錯分的音符。初學顯示「高一點／低一點」，進階顯示 C4、音分與參考調音。

**初學者如何判斷**：點選一個音符會播放原人聲及可選的簡單參考音；先比高低方向，不要求說出音名。

**接受標準**：乾淨測試音的音高讀值誤差門檻建議為中位數 10 音分以內；靜音、呼吸和無聲子音不得一律生成有音高的音符；提供辨識不足與八度疑似錯誤狀態；分析不改動音訊。

**限制與依賴**：需區分有聲／無聲、音高追蹤、音符切分三步。多個人同唱時不得呈現一條假裝精準的主唱曲線。多音轉 MIDI 也不能保證分清整首歌每件樂器。

**技術來源**：[librosa 基頻分析說明](https://librosa.org/doc/dev/auto_tutorials/01-intro/03-f0.html)提供有聲判定與基頻概念；[Spotify Basic Pitch](https://github.com/spotify/basic-pitch)可作音符轉寫候選，官方指出單一樂器效果最好；[RMVPE 原始論文](https://arxiv.org/abs/2306.15412)是人聲基頻估測候選，估測能力不等於可直接無損修改混音。

## 第二層 修改已經錄好的演唱

### F05 自然修音與逐音符修正

**白話目的**：把偏高或偏低的地方稍微拉回來，保留原本演唱的感情與滑音。

**UI 動作**：選人聲 → 確認旋律參考 →「輕輕調準」；可拉單一音符高低，分別調「靠近目標多少」「多久靠過去」「保留顫音」。保留一鍵「恢復這個音」。

**初學者如何判斷**：先用參考音聽目標，再比較整句是否順；如果每個尾音都像直線、轉音突然跳格，修正可能太強。

**接受標準**：0% 修正需旁路且不改變長度；在已知目標、持續至少 200 毫秒的乾淨穩定測試音上，100% 校正後中段中位音高與目標的差距建議不超過 10 音分；無聲子音不強行變調；顫音保留開關需以測試曲線與聽感核驗。

**限制與依賴**：音高偵測只知道唱了什麼，未必知道原本想唱什麼。「靠近最近音階音」可能把創作中的音改錯。先支援單旋律人聲；和聲或合唱需分開後處理。較大幅度修正不承諾自然。

**技術來源**：[Rubber Band 整合說明](https://www.breakfastquay.com/rubberband/integration.html)涵蓋動態變調、音色保留與即時／離線選項；它是聲音變換元件，音符目標、修正曲線及偵測仍須另外建立。

### F06 整句移調與共振峰控制

**白話目的**：讓整句旋律一起升高或降低；也可在不改旋律的情況下試聲音質地。

**UI 動作**：「整句升高一格（1 半音）」「整句降低一格」「保留原本聲音質地」；進階區另放「共振峰偏移」，不把它叫作換歌手。

**初學者如何判斷**：整句移調後，音與音之間的走向應保持；若聲音突然像卡通角色，可比較是否保留共振峰。改共振峰時，主要旋律應仍相同。

**接受標準**：純移調模式不改總長；純變速模式不改目標音高；零移調採真正旁路；立體聲聲道維持同步；保留共振峰開關輸出可核實。

**限制與依賴**：普通播放速度控制會同時改變音高與時長，不能冒充獨立移調。大幅移調仍可能出現音色失真；升降全曲也會改變所有伴奏的音高。

**技術來源**：[Rubber Band 整合說明](https://www.breakfastquay.com/rubberband/integration.html)與 [Ableton 官方變速及共振峰說明](https://www.ableton.com/en/live-manual/11/audio-clips-tempo-and-warping/)。

### F07 調性與和弦參考

**白話目的**：提供「這裡可以先試哪些音」的參考，幫助選擇修音目標或新增旋律。

**UI 動作**：「分析這段的調性」→ 顯示候選及不確定區段 → 使用者可選「先用這個當參考」；和弦用獨立時間列顯示，能手動修改。允許完全不選調性。

**初學者如何判斷**：按和弦卡片播放簡單示範，與伴奏比較是否相容；若聽起來不對，換候選或保留未設定，不要求相信分析器。

**接受標準**：分析只新增參考資料；支援段落換調；人工指定可覆蓋估測且在重開專案後保留；無可靠結果時顯示「暫時無法判斷」。未經校準的模型分數不能顯示成「正確率 97%」。

**限制與依賴**：整曲調性不等於每個和弦。大／小調估測也不涵蓋所有調式；複雜和弦、轉位與鼓聲可能干擾結果。不預設把非調內音全部修掉。

**技術來源**：[Essentia Key 文件](https://essentia.upf.edu/reference/streaming_Key.html)輸出 key、scale 與 strength；strength 並不應直接包裝為校準後的正確機率。和弦辨識需另選模型／演算法。

### F08 速度 拍點與小節格線

**白話目的**：把音樂的「一、二、三、四」放到畫面上，之後才知道唱早或唱晚。

**UI 動作**：「找節拍」→ 顯示 BPM 及拍點 → 開節拍器確認 →「這裡是第一拍」；提供「速度乘二／除二」「手動點拍」「此段速度不同」。

**初學者如何判斷**：聽節拍器是否持續跟住歌曲，並分辨它是每拍都點、只點強拍，還是速度判成兩倍。不要只看 BPM 數字漂亮。

**接受標準**：乾淨等間距測試鼓點的 BPM 誤差建議不超過 0.5%，拍點中位誤差不超過 20 毫秒；第一拍能人工指定；自由速度錄音可建立 tempo map；不把 beat 結果自動當 downbeat。

**限制與依賴**：BPM、拍點、第一拍、拍號是不同資料。弱鼓、自由節奏與變拍會增加不確定性。節拍分析器可能需要先讀完整段落，不應偽裝即時分析。

**技術來源**：[Essentia RhythmExtractor2013](https://essentia.upf.edu/reference/std_RhythmExtractor2013.html)提供 BPM、拍點及特定方法的信心分數；[官方教程](https://essentia.upf.edu/tutorial_rhythm_beatdetection.html)說明該法不適合即時偵測。downbeat／meter 應另做模型或人工流程。

### F09 不改音高的快慢與局部時間拉伸

**白話目的**：把歌曲放慢聽清楚，或讓一句唱快／唱慢一點，旋律高低仍保持。

**UI 動作**：「慢一點聽」只影響試聽；「套用到片段」才寫入編輯。波形放時間錨點，可固定前後位置，只拉中間一個字；提供人聲、鼓、完整混音的適用模式。

**初學者如何判斷**：慢下來之後，歌手不應突然整個聲音變低；編輯鼓時聽撞擊是否變軟，人聲則聽子音與尾音是否破碎。

**接受標準**：試聽速度不改專案；套用後目標片段長度符合設定且錨點不互相跨越；拉伸前後與相鄰片段無意外空白或重疊；演算法延遲得到補償。

**限制與依賴**：不宣稱任意比例都自然。建議先以 0.8–1.2 倍作基礎品質驗收，再用更大比例測極端行為；這是測試範圍，不是通用無損界限。拉伸合成的聲音仍須聽感驗收。

**技術來源**：[Rubber Band 時間拉伸整合文件](https://www.breakfastquay.com/rubberband/integration.html)說明即時處理的前置補樣、起始延遲及離線處理差別。

### F10 節奏修正 搖擺與律動

**白話目的**：把太早或太晚的字／鼓點稍微拉齊，也能保留刻意的鬆弛感。

**UI 動作**：選起音 → 選 1/8、1/16 或三連音格線 →「往拍點靠近 30%」；另外提供「前後搖擺」及「跟這段的律動」。先顯示預計移動量，確認後套用。

**初學者如何判斷**：同一段輪流聽原版、輕量對齊、完全對齊；如果像機器而不是更順，可以減少強度。學會有意識選擇，不把貼齊格線當唯一正解。

**接受標準**：0% 不移動，100% 到指定目標；變更只作用於選中的起音；可排除某些字、設定最大移動幅度；多麥克風同錄的群組必須共用時間變換，保留相互時序。

**限制與依賴**：依賴可靠拍格、起音點與 F09 拉伸。人聲子音開始與母音開始不完全相同，需可選對齊基準。鼓組多軌不可各自隨意拉伸，以免破壞相位關係。

**技術來源**：[Ableton 官方量化與 Warp 說明](https://www.ableton.com/en/live-manual/11/audio-clips-tempo-and-warping/)提供格線、起音與部分量化的可行互動模式；WaveForge 的群組驗收另行建立。

### F11 換成另一段錄音與多次演唱拼接

**白話目的**：把這一句換成自己或別人重新錄好的版本，或從多次演唱中挑最滿意的句子。

**UI 動作**：選原人聲範圍 →「換上另一段錄音」→ 匯入／錄一段 → 對齊開頭及幾個字 → 選需要的句子 → 調接縫、音量及空間感。提供原版與候選 take 軌。

**初學者如何判斷**：聽有沒有同一句唱兩次、字被切掉、跟伴奏錯拍，或一句突然像換了房間錄音。先修時間，再修音量與音色。

**接受標準**：只在選取範圍停用原人聲；伴奏不因此變動；原版可一鍵恢復；接縫有可調交叉淡化；48 kHz 新錄音與 44.1 kHz 專案的匯入不產生速度或音高錯誤；輸出起點和長度可精確對齊。

**限制與依賴**：自動對齊應先限相同歌詞、相近旋律。字數或旋律差很多時改用手動錨點。新錄音若含伴奏，要先處理重複伴奏；原伴奏若殘留舊人聲，也不能保證完全乾淨地換掉。此功能不需要 AI 聲音模型。

**技術來源**：片段排程可用 [Web Audio API](https://www.w3.org/TR/webaudio-1.0/)；局部伸縮可用 [Rubber Band](https://www.breakfastquay.com/rubberband/integration.html)。自動歌詞對齊是額外辨識工作，不等於直接互相關即可處理所有演唱。

### F12 人聲音量 氣息與清晰度

**白話目的**：讓每一句聽得清楚，保留想要的輕重、氣聲與咬字。

**UI 動作**：句子音量線「這句大聲一點」；壓縮「收住忽大忽小」；EQ「減少悶／增加明亮」；de-esser「收一點刺耳的嘶聲」；呼吸片段可單獨調小或保留。

**初學者如何判斷**：放回伴奏中聽字是否比較容易懂；如果呼吸突然被抽掉、字頭變鈍、聲音一直喘動，就減少處理。每個效果都有等音量前後對照。

**接受標準**：每個控制對應真實 DSP 與可測響應；只開 EQ 不應暗中啟動壓縮；旁路恢復；增益／動態控制不造成未提示削波；單獨壓低呼吸片段不影響其他句。

**限制與依賴**：EQ、壓縮、氣聲處理可改聽感，不能把已錄好的含糊音節任意變成完全不同咬字。深度「重新咬字」應走 F16／F17 的重唱流程。

**技術來源**：[Web Audio 標準節點](https://www.w3.org/TR/webaudio-1.0/)可支援基礎增益、濾波與動態處理；更進階去齒音及呼吸偵測須增加專用 DSP／分析。

## 第三層 AI 聲音與改詞重唱

### F13 保留唱法的 AI 音色轉換

**白話目的**：把已經唱好的表演換成另一種聲音，盡量保留唱什麼、何時唱與旋律走向。

**UI 動作**：選單獨人聲 →「換音色，保留這次唱法」→ 選已授權模型 → 先產生 5–15 秒預覽 → 比較 → 套用選段。可選保留原音高，或明確指定整體移調。

**初學者如何判斷**：除了像不像目標聲音，也要聽歌詞是否仍清楚、氣息是否怪異、尾音是否斷裂、原本細微轉音是否被吃掉。

**接受標準**：輸出回到正確專案時間、長度與聲道規格；保留原歌詞模式不得默默更換文字；固定素材、模型、參數與種子在支援確定性時可重現；不支援時保存實際生成音訊作正式結果；模型不存在或授權未核實時不能顯示成功。

**限制與依賴**：來源分離瑕疵會被帶進轉換；模型支援音域、語言及氣聲表現有限。不能承諾上傳任意幾秒聲音就完美複製任意歌手。RVC 類轉換沒有把新歌詞唱出來的完整能力，也不能保證原本每個呼吸細節完全不變。

**技術來源**：[RVC 官方英文文件](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/blob/main/docs/en/README.en.md)是音色轉換候選。其程式授權與聲音模型、資料集及聲音使用者同意需分開查驗。

### F14 聲音模型與授權管理

**白話目的**：讓使用者知道「這個聲音從哪裡來、能不能用在自己的作品、要不要付費」。

**UI 動作**：模型卡顯示聲音提供者、可用語言／音域、用途限制、是否允許商用、是否需署名、本機或雲端處理。自訂聲音要有可核對的權利及同意紀錄；使用者先查看成本與目的地再開始。

**初學者如何判斷**：分清「可下載模型」和「可公開發布歌曲」不是同一件事；看不懂或沒有授權資料的聲音先不使用。

**接受標準**：聲音權利、模型授權及資料來源各有欄位；缺少必要資訊時停在待確認；撤銷權利後阻擋新生成；產出保留生成方式與模型版本；雲端傳輸、保留期間及刪除選項清楚可見。

**限制與依賴**：開源程式碼不自動授權他人的聲音、歌詞、錄音或訓練資料。來源不明的序列化模型不可直接在可信任主程序執行。先以權利清楚的聲音庫與自有演唱測試。

**技術來源**：[RVC MIT 授權](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/blob/main/LICENSE)只描述程式授權；[OpenVPI DiffSinger 官方專案](https://github.com/openvpi/DiffSinger)另外明示聲音同意要求。完整商用審查需按選定模型逐一完成。

### F15 歌詞辨識與逐字時間軸

**白話目的**：點畫面上的一句歌詞，就能找到錄音裡那一句，準備換字或重唱。

**UI 動作**：「帶入歌詞」優先接受使用者提供的文本，也可「先辨識草稿」；逐句確認後顯示字／音節與時間位置。多音字、外語、拖長音可手動指定讀音和分配。

**初學者如何判斷**：跟著播放指示讀歌詞，檢查字對不對、每個字有沒有跟聲音對上。看不清或辨識不出的地方保留空白／疑問，不自行補滿。

**接受標準**：辨識文字是可編輯草稿，不自動改音訊；人工修正保留；一句修改不覆蓋其他已確認句；無歌聲處不生成確定歌詞；時間對齊可人工調整。

**限制與依賴**：語音辨識模型不等於已驗證的歌聲辨識器。伴奏、合唱、重複副歌與拖長音會影響結果；逐字對齊要另驗證，不把一般字幕時間直接當精確音素邊界。

**技術來源**：[Whisper 官方 model card](https://github.com/openai/whisper/blob/main/model-card.md)是語音轉文字候選的限制查核入口；WaveForge 仍需建立歌唱測試集及字／音節對齊流程。

### F16 保留旋律的改詞重唱

**白話目的**：把「想你」改成「等你」，讓指定聲音按原旋律重新唱出新詞。

**UI 動作**：選一句 →「改歌詞並重唱」→ 改文字 → 選保留旋律／重新調旋律 → 配置每個字唱幾個音、多久 → 選授權歌聲 → 產生候選 → 聽接縫 → 保留喜歡的版本。

**初學者如何判斷**：先確認唱的是新詞、讀音正確；再聽是否擠字、空拍太長、拖音奇怪；最後聽它與前後句的音色和表情是否接得上。

**接受標準**：UI 區分「只改畫面文字」與「真的重新產生聲音」；支援的語言與讀音需明示；新增或刪除音節時提示重新分配時間；合成錯誤不覆蓋原句；選段以外的原始片段不重生成，僅允許明示的接縫範圍改變。

**限制與依賴**：依賴 F04 音符、F15 歌詞／音節時序、合適歌聲模型、歌聲合成及接縫處理。不能只改字幕，也不能只送一般 TTS。不同字數和母音會改變自然時長與發音，無法保證與舊唱法逐 sample 相同。

**技術來源**：[OpenVPI DiffSinger](https://github.com/openvpi/DiffSinger)是可控歌聲合成的候選路線；[Dreamtonics Synthesizer V 官方產品頁](https://www.dreamtonics.com/synthesizerv/)展示歌詞、旋律與音素控制的成熟工作方式。產品頁不代表提供可嵌入 WaveForge 的 API 或授權。

### F17 重新唱法與局部表情控制

**白話目的**：同樣歌詞和旋律，試比較輕、比較有力、氣聲多一點或咬字清楚的演唱。

**UI 動作**：選生成的人聲句 →「再唱一次」→ 選一個表情方向，或調整音素時長、音量、氣聲與音高曲線 → 產生少量候選並列比較。

**初學者如何判斷**：問「這句更符合歌詞的情緒嗎」「字是不是仍清楚」，不把更大聲當成更有感情。必要時同音量比較。

**接受標準**：固定歌詞與音符模式不擅自改詞／改旋律；不受模型支援的控制隱藏或明確標示；每次候選保存版本；最多同時生成多少候選、所需費用和取消方式可見。

**限制與依賴**：各模型可控制的參數不同；「情緒 80%」若沒有可驗證定義就不顯示精密數字。真人錄音上的 EQ 不能冒充重新演唱；錄音型與合成型人聲需分清。

**技術來源**：[OpenVPI DiffSinger](https://github.com/openvpi/DiffSinger)列有音高、能量與氣聲等可控變量；[Synthesizer V Studio 2 官方公告](https://dreamtonics.com/announcing-synthesizer-v-studio-2-pro/)可作 retake、音素時序等互動參考，具體模型能力仍需實測。

## 第四層 將這些能力接成可完成作品的 DAW

### F18 簡易鋼琴卷軸與 MIDI

**白話目的**：不用重新唱，也能把某個音改高、拉長、加一個音，作為重唱或樂器演奏的旋律。

**UI 動作**：打開「旋律方塊」→ 上下拖改高低、左右拖改時間、拉邊緣改長短 → 用簡單鋼琴聲預聽 → 送到歌聲合成；支援 MIDI 匯入匯出。

**初學者如何判斷**：先用乾淨、單一樂器音色聽旋律是否對，再换成歌聲；點方塊可以看對應歌詞，不必先熟悉五線譜。

**接受標準**：MIDI 音高、開始時間、時長與 tempo map 匯出重讀一致；歌詞與一字多音的關係可保存；錄音分析產生的音符要標示為可修正結果；合成預覽與採用的音符版本一致。

**限制與依賴**：MIDI 是演奏指令，不是原來聲音。從音訊轉成 MIDI，不能保證保留歌手音色與全部表情；完整樂器庫與外掛宿主可晚於人聲功能。

**技術來源**：[Spotify Basic Pitch](https://github.com/spotify/basic-pitch)輸出含 pitch bend 的 MIDI；其結果仍需校正與合適合成器才能重新發聲。

### F19 編曲段落與混音自動化

**白話目的**：複製副歌、縮短前奏，讓某句人聲大聲一點，並把多軌放進共同空間。

**UI 動作**：標記「主歌／副歌」→ 群組移動或複製；畫音量、左右位置、效果量的變化線；建立人聲群組及混響傳送。母帶區保持在最後一層。

**初學者如何判斷**：段落移動後，歌詞、鼓與伴奏是否一起走；自動化前後是否自然；混響要放回整體聽，避免獨聽很美、整首卻模糊。

**接受標準**：段落操作同步移動音訊、音符、歌詞和相關自動化；群組靜音、solo 與路由行為一致；匯出包含所有啟用自動化；工程保存後能恢復路由。

**限制與依賴**：依賴統一時間座標與路由圖。必須先定義效果順序、send 是推桿前或後、solo 對傳送的行為；不能只有看得到的曲線卻沒有聲音變化。

**技術來源**：[Web Audio API](https://www.w3.org/TR/webaudio-1.0/)支援節點連接與參數自動化；DAW 路由、群組與時間資料一致性需自行實作。

### F20 正式匯出與試聽一致

**白話目的**：確保下載的檔案，包含剛剛聽到的人聲替換、修音、節奏和效果。

**UI 動作**：「匯出整首」「匯出人聲」「匯出全部音軌」；先選範圍、取樣率、位元深度與尾音保留，再產生「最終品質預聽」。專業術語旁附簡短說明。

**初學者如何判斷**：先重聽新改的句子和曲尾；確認沒有舊人聲、缺字、爆音或混響被切掉，再分享。

**接受標準**：所有匯出 stem 共同起點與共同長度，需保留的前段靜音不被各自裁掉；相同引擎、設定與無損格式的確定性測試可作 null test；匯出結果重匯入後與最終品質預聽時間一致；原本有聲的處理範圍不得輸出空白。

**限制與依賴**：即時省電預覽與離線高品質可能有細微差異，必須清楚區分；正式預聽使用正式渲染結果。不能只要求「用了相同滑桿」就認定聲音一致。MP3 等有損輸出不要求逐 sample 等同 WAV。

**技術來源**：[Web Audio OfflineAudioContext](https://www.w3.org/TR/webaudio-1.0/)提供離線渲染機制；[Rubber Band 整合說明](https://www.breakfastquay.com/rubberband/integration.html)提醒即時與離線路徑的延遲處理差異。

### F21 大型處理 任務狀態與失敗恢復

**白話目的**：長歌分離或 AI 重唱需要等候時，知道正在做什麼，不必擔心原檔被弄壞。

**UI 動作**：處理前顯示本機／伺服器、預估時間區間與成本；處理中顯示排隊、分析、產生、完成；能取消，失敗可重試；只有完成的結果能採用。

**初學者如何判斷**：清楚分辨「已送出」「處理中」「有可聽結果」。進度 100% 必須能按播放，而不是只有綠色提示。

**接受標準**：任務具唯一 ID、素材雜湊、模型版本、參數及結果檔；重按不重複計費；取消不覆蓋專案；失敗不留下看似有效的空片段；已生成結果離開頁面後能恢復。時間估計需基於已測硬體／服務資料，不憑空顯示秒數。

**限制與依賴**：瀏覽器可能中斷背景頁籤或遇到記憶體上限，不能保證長時間訓練和即時 AI 都能在所有裝置完成。雲端費用、保留政策與模型下載需獨立核實及授權。

**技術來源**：[ONNX Runtime Web](https://onnxruntime.ai/docs/tutorials/web/)可作瀏覽器推論路線；[官方執行選項](https://onnxruntime.ai/docs/tutorials/web/env-flags-and-session-options.html)列出 worker、WASM 多執行緒與跨來源隔離的限制。實際音訊模型能否轉換和運行需另測。

## 技術分工建議

### 瀏覽器優先處理

適合放在瀏覽器的第一批功能：多軌介面、片段剪接、短段循環、參數自動化、基本混音、波形／音高圖、可負擔的分析、MIDI 編輯與任務管理。

- 音訊播放與輕量 DSP 用 AudioWorklet 或標準 AudioNode，避免用 UI 主執行緒驅動音訊時間
- 分析、解碼與推論放 worker；音訊 callback 裡不能做耗時模型工作或大量配置記憶體
- 採用 WASM 或 WebGPU 前先做功能探測、模型算子支援與基準測試；不以「瀏覽器有 GPU」推論一定能跑所有模型
- 必要時提供可取消的分段離線渲染與凍結音軌，減少同時即時運算

### 桌面或本機服務適合處理

較大模型、本機隱私需求、GPU 加速與較長歌曲的分離／轉換，可由桌面程式或本機 worker 處理。瀏覽器負責編輯，後端只接具版本的明確處理任務，回傳音訊與必要分析資料。

桌面也不能自動繞過程式／模型授權。原生 VST／AU 宿主是另一項大型能力，與完成換錄音、修音、歌詞重唱沒有必要綁成第一期。

### 伺服器適合處理

需要一致 GPU 環境的分離、音色轉換與歌聲合成，可提供伺服器工作。每次處理前顯示資料目的地、保留政策與費用，支援刪除、取消、重試與結果下載。使用者沒有同意雲端傳輸時，保留本機可做的功能。

聲音合成引擎先做可更換介面：輸入明確的歌詞、音素、音符、時間、表情與聲音模型；輸出音訊、對齊資訊及版本。商業產品存在，不代表可直接當後端 API 使用。

## 必須先建立的共同資料模型

- **AudioAsset**：原檔、來源、取樣率、聲道、長度與內容雜湊
- **Clip／Take**：引用哪個原檔、開始位置、入點出點、淡化、候選版本；不靠反覆覆寫 WAV 實現復原
- **TempoMap／MeterMap**：拍點、小節、拍號、速度變化及人工校正
- **PitchTrack／NoteEvents**：連續基頻、有聲判定、音符邊界、可信度資料及人工修正
- **Lyrics／PhonemeAlignment**：文字、讀音、音節／音素時序、一字多音及確認狀態
- **EditGraph**：增益、EQ、修音、拉伸、路由及自動化的順序
- **VoiceModel／RightsRecord**：模型、權利來源、適用範圍、版本與限制
- **RenderJob／RenderedAsset**：輸入版本、參數、處理引擎、狀態、結果與採用紀錄

分析用降採樣副本與正式音訊分開；不能把模型的 16 kHz 或 22.05 kHz 輸入副本直接當高品質正式輸出。所有音符、歌詞與節拍資料都要有可回到原始音訊的時間座標。

## 建議建置順序

### 階段 A 可信任的編輯與比較

先完成 F01–F03、F11 的手動對齊版本、F20 及基本 F21。這時使用者已能把另一段錄音真正換進歌曲，保存工程並下載一致的結果。

**放行條件**：用一首 3–5 分鐘測試歌曲完成匯入、換一句、復原、再採用、儲存重開、匯出重聽；不能有錯位、舊版混入或音訊遺失。硬體與瀏覽器測試範圍另行固定。

### 階段 B 看懂旋律與節奏再進行修正

完成 F04–F10、F12，以及 F18 最小音符編輯。先有手動目標和手動拍點，再加自動建議，避免自動辨識成為所有操作的單一故障點。

**放行條件**：使用者不讀音名，也能依白話引導完成「這個字早一點」「這個音低一點」，並明確聽到／看見對應變化；不確定分析可被略過。

### 階段 C 保留演唱的音色轉換

完成 F13、F14 與完整 F21。先使用一個權利清楚、適合歌唱的模型跑通選段預覽、套用、正式匯出，再擴充模型庫。

**放行條件**：至少覆蓋低音、高音、氣聲、快字、長音與安靜片段；歌詞、起止時間、伴奏不受意外改動；提供失敗例子與適用範圍，不只展示最佳 demo。

### 階段 D 改詞與重新演唱

完成 F15–F17，擴充 F18，接上 F19 的段落和自動化。先支援一種已驗證語言及有限歌聲，再增加跨語言與複雜表情。

**放行條件**：一個字換一個字、字數增加、字數減少、多音字、同一字跨多個音都能檢查並修正；結果含新詞，舊句仍可恢復，接縫自然度有真人聽測。

以上是依賴順序，不是刪除後期需求，也不是未估算工時前的交付承諾。

## 共通驗收與品質門檻

### 確定性功能

用已知起點的脈衝、固定音高、音高滑動、不同聲道訊號、靜音與短句測試排程、移調、拉伸、路由及匯出。測試應記錄取樣率、瀏覽器／桌面版本與引擎版本。

F04、F05、F08 所列數字只針對可控制的乾淨測試訊號。不能把它們宣稱為所有真實歌曲的準確率。

### 真實音樂與 AI 功能

建立獲授權的測試集，含清唱、伴奏、和聲、殘響、rap、自由速度、換調、多語言與多種音域。分別評估：

1. 字是否唱對與讀音是否清楚
2. 音高及節奏是否達到指定目標
3. 是否有破碎、水聲、金屬感、突然變音色
4. 與前後句是否接得自然
5. 生成是否真的侷限在指定範圍

音質以等音量盲聽及成對偏好比較補充，不用單一模型評分替代人的判斷。真人測試通過門檻應在正式測試前確立，不能看完結果再改標準。

### 出口安全檢查

- 原始素材始終可取回；歷史版本不被背景任務覆蓋
- 點預覽、點採用、點匯出使用同一個已驗證版本
- 取消、斷網、空間不足、重新整理、重複按鈕與模型錯誤都不損壞工程
- 昂貴工作開始前有價格／用量與目的地提示；不可只在失敗後才告知花費
- 所有分析值標清楚是「估測」「使用者指定」或「已確認」，不製造不實精準感
